# Database Schema Conventions

**Status: binding.** Every migration PR is checked against this document. If you need an
exception, get Tech Lead sign-off in the PR *before* merging. Reviewers: reject PRs that
deviate silently.

Related: `docs/database-schema.md` (the master table definitions), `docs/architecture.html`
(system/flow design), ADR 0001 (identity & photo), ADR 0002 (billing), `docs/dev-setup.md`.
On conflicts: ADRs → database-schema.md → this document.

---

## 1. Golden rules (read this even if you read nothing else)

1. Every table's primary key is `id UUID` — generated by the database, never by the app, never sequential integers.
2. Business identifiers (UHID, THID, token numbers, receipt numbers) are **separate columns**, never the primary key.
3. All names `snake_case`. Tables plural (`patients`), columns singular (`first_name`).
4. Every table has `created_at` / `updated_at` (`timestamptz`, UTC). Every human-caused row also has `created_by`.
5. Status values come from **section 7 of this doc** — never invent your own strings.
6. Money is `NUMERIC(12,2)`. Never `float`/`real`/`double`.
7. Aadhaar is never stored or logged in plaintext, and never used as a key. Blind index + encrypted blob only.
8. No hard deletes on clinical or financial data — soft delete or append-only.
9. Use the shared SQLAlchemy mixins in `app/common/models.py`. Do not hand-roll `id`/timestamp columns.
10. One migration per PR, numbered per the plan (section 12), with a working `downgrade()`.

## 2. Primary keys and identifiers

### 2.1 Primary key — every table, no exceptions

```sql
id UUID PRIMARY KEY DEFAULT uuid_generate_v4()
```

Why UUID: this is an offline-resilient edge-cloud system. Rows created at a facility
while offline must merge into cloud Postgres without collisions. Auto-increment integers
collide; UUIDs don't.

In SQLAlchemy, inherit the mixin — don't declare `id` yourself:

```python
from app.common.models import UUIDPk, Timestamps

class Patient(Base, UUIDPk, Timestamps):
    __tablename__ = "patients"
```

### 2.2 Business identifiers (human-facing)

Stored as their own `UNIQUE NOT NULL` (or nullable, where stated) columns:

| Identifier | Column | Format | Generated by |
|---|---|---|---|
| UHID | `patients.uhid` | `IN-<STATE>-<FACILITY>-<YEAR>-<SEQ6>-<CHECK>` e.g. `IN-RJ-JPR001-2026-000042-7` | UHID engine (B2-W1-02), Postgres sequence + check digit |
| THID (temporary) | `patients.thid` | `TH-<FACILITY>-<YYMMDD>-<SEQ4>` e.g. `TH-JPR001-260714-0007` | Emergency registration; merged into UHID later (audited) |
| Queue token | `queue_tokens.token_display` | `<DEPT_CODE>-<SEQ3>`, e.g. `MED-042`; uniqueness = `(queue_id, sequence)`, not the string | Queue service, per doctor-queue per day |
| Order number | `orders.order_number` | `ORD-<YYYYMMDD>-<SEQ6>` | Orders module |
| Invoice number | `invoices.invoice_number` | `INV-<FACILITY>-<YYYYMMDD>-<SEQ5>` | Billing (gapless — see 2.3) |
| Receipt number | `payments.receipt_number` | `RCP-<FACILITY>-<YYYYMMDD>-<SEQ5>` | Billing (gapless — see 2.3) |
| Refund number | `refunds.refund_number` | `RFD-<FACILITY>-<YYYYMMDD>-<SEQ5>` | Billing (gapless) |
| Lab accession | `lab_order_items.accession_number` | `LAB-<YYYYMMDD>-<SEQ5>` | Lab module |
| Radiology accession | `radiology_order_items.accession_number` | `RAD-<YYYYMMDD>-<SEQ5>` | Radiology module |
| ABHA | `patients.abha_number` | as returned by ABDM V3, stored verbatim, nullable | ABDM Gateway |

Rules:

- Formats above are **frozen**. Changing one is an ADR, not a PR comment.
- Sequences: one Postgres sequence per generator, named `seq_<purpose>` (e.g. `seq_uhid_jpr001_2026`). Never `MAX(col)+1` — it races.
- Invoice/receipt/refund numbers must be **gapless** for financial audit: allocate inside the payment transaction using a counters table with `SELECT ... FOR UPDATE`, not a Postgres sequence (sequences leave gaps on rollback).
- Foreign keys always reference `id` (the UUID), never a business identifier.

### 2.3 What the API exposes

API responses include both: `"id"` (UUID, for machines) and the business identifier
(for humans). URLs use the UUID: `/api/v1/patients/{uuid}`.

## 3. Naming

| Thing | Convention | Example |
|---|---|---|
| Table | plural snake_case | `patient_identifiers` |
| Column | singular snake_case | `first_name` |
| FK column | `<referenced_table_singular>_id` | `patient_id`, `visit_id` |
| Self/role-qualified FK | `<role>_<table_singular>_id` | `approved_by_user_id`, `merged_into_patient_id` |
| Boolean | `is_` / `has_` prefix | `is_active`, `has_allergies` |
| Timestamp event | `<verb>_at` | `dispensed_at`, `discharged_at` |
| Actor of event | `<verb>_by` (UUID → `users.id`) | `dispensed_by` |
| Enum-like column | noun, values from §7 | `status`, `identity_path` |
| Index | `ix_<table>_<cols>` | `ix_patients_uhid` |
| Unique constraint | `uq_<table>_<cols>` | `uq_patients_uhid` |
| Check constraint | `ck_<table>_<name>` | `ck_orders_status` |
| FK constraint | `fk_<table>_<col>` | `fk_visits_patient_id` |
| Sequence | `seq_<purpose>` | `seq_uhid_jpr001_2026` |
| Trigger | `trg_<table>_<purpose>` | `trg_audit_logs_block_update` |

You don't need to name indexes/constraints manually — the naming convention is wired
into SQLAlchemy metadata (`app/common/db.py`), so autogenerate produces these names.
Just don't override them.

Abbreviations: only these are allowed in names — `id`, `uhid`, `thid`, `abha`, `otp`,
`icd`, `fhir`, `grn`, `ot`, `ipd`, `opd`. Everything else spelled out
(`prescription` not `rx`, `department` not `dept`).

## 4. Standard columns

Every table (via `Timestamps` mixin):

```sql
created_at  timestamptz NOT NULL DEFAULT now(),
updated_at  timestamptz NOT NULL DEFAULT now()   -- app updates on every write
```

Tables where a person causes the row (almost all of them):

```sql
created_by  UUID NOT NULL REFERENCES users(id),
updated_by  UUID REFERENCES users(id)
```

Facility-scoped tables (any table whose rows belong to one hospital — patients, visits,
queue_tokens, stock, ...):

```sql
facility_id UUID NOT NULL REFERENCES facilities(id)
```

Rules:

- All timestamps `timestamptz`, stored UTC. Convert to IST in the frontend only. Never `timestamp without time zone`, never store local time.
- `updated_at` is also the offline-sync conflict field — it must be accurate. The `Timestamps` mixin handles it; don't write it manually.

## 5. Deleting data

| Data class | Policy | Mechanism |
|---|---|---|
| Clinical (encounters, diagnoses, results, prescriptions) | **never delete, never overwrite** | append-only or versioned (§6) |
| Financial (invoices, payments, refunds) | never delete | immutability trigger + reversal rows only |
| Audit / access logs | never delete, never update | DB trigger blocks UPDATE/DELETE (B7-W1-01) |
| Master data (departments, medicines, users) | soft delete | `is_active boolean NOT NULL DEFAULT true` |
| Operational mistakes (mis-created patient) | soft delete + audit | `deleted_at timestamptz NULL` + `deleted_by`; a row is deleted iff `deleted_at IS NOT NULL` |
| Join/queue ephemera (expired tokens) | hard delete allowed | scheduled cleanup job only |

Use `is_active` for "retired from use", `deleted_at` for "should not have existed".
Not both on the same table.

## 6. Append-only and versioned tables

Append-only (INSERT only; trigger rejects UPDATE/DELETE): `audit_logs`,
`data_access_log`, `file_access_log`, `stock_ledger`, `patient_merge_log`.

Versioned results (lab/radiology, B5-W1-01): corrections are **new rows**, never updates:

```sql
result_versions (
  id UUID PK,
  result_id UUID NOT NULL REFERENCES results(id),
  version integer NOT NULL,            -- 1, 2, 3...
  is_current boolean NOT NULL,         -- exactly one true per result_id (partial unique index)
  superseded_by UUID NULL REFERENCES result_versions(id),
  ...payload, created_at, created_by
)
```

## 7. Canonical enumerated values

**Implementation:** `varchar(50)` + `CHECK` constraint (named `ck_<table>_<col>`), values
lowercase snake_case. We do **not** use native Postgres `ENUM` types (painful to alter
in migrations). Define each value set once in `app/common/enums.py` as `str` Enums and
reuse — frontend gets them from the OpenAPI schema.

These are the shared vocabularies. **Adding a value = PR touching `enums.py` + this doc,
reviewed by Tech Lead. Never add a bare string in your own module.**

| Domain | Column | Values |
|---|---|---|
| Sex | `patients.sex` | `male`, `female`, `other`, `unknown` |
| Identity path (ADR 0001) | `registrations.identity_path` | `abdm`, `thid`, `aadhaar_mobile`, `demographics_only` |
| Identity flags | `patients.identity_status` | `verified`, `identity_unverified`, `photo_pending` |
| Visit type | `visits.visit_type` | `opd`, `ipd`, `emergency`, `teleconsult` |
| Visit status | `visits.status` | `registered`, `in_queue`, `in_consultation`, `admitted`, `discharged`, `closed`, `lwbs` (left without being seen) |
| Queue token | `queue_tokens.status` | `waiting`, `called`, `in_service`, `completed`, `no_show`, `cancelled` |
| Order status | `orders.status` | `placed`, `accepted`, `in_progress`, `completed`, `cancelled` |
| Result status | `results.status` | `pending`, `preliminary`, `final`, `corrected` |
| Prescription item | `prescription_items.status` | `prescribed`, `partially_dispensed`, `dispensed`, `substituted`, `cancelled` |
| Invoice (ADR 0002) | `invoices.status` | `draft`, `issued`, `partially_paid`, `paid`, `waived`, `cancelled` |

| Sync sensitivity | any synced table `sensitivity` | `normal`, `important`, `critical` (critical = never auto-resolved, e.g. payment receipts) |

## 8. Sensitive and personal data

| Field | Storage | Never |
|---|---|---|
| Aadhaar | `aadhaar_blind_index char(64)` (HMAC-SHA256, key from env — B2-W1-03) + `aadhaar_encrypted bytea` (AES-GCM) | plaintext column, logs, indexes on plaintext, PK/FK use |
| ABHA number | plaintext ok (it's a health ID by design), `abha_number varchar(17)` | using it as PK |
| Mobile | `mobile varchar(20)`, E.164 (`+91XXXXXXXXXX` — 15 digits + leading `+`) | storing formatting variants |
| Patient photo | MinIO object, DB stores `file_id` reference | bytea in Postgres, public bucket |
| Passwords | nowhere — Keycloak owns credentials | any password column |

Duplicate check on Aadhaar = equality on `aadhaar_blind_index`. That's its only purpose.

## 9. Money

```sql
amount NUMERIC(12,2) NOT NULL CHECK (amount >= 0)
currency char(3) NOT NULL DEFAULT 'INR'
```

Negative amounts are forbidden — a refund is a row in `registration_refunds` with a
positive amount, not a negative payment.

## 10. Foreign keys, indexes, JSON

- Every FK column gets a real `FOREIGN KEY` constraint. Default `ON DELETE RESTRICT`. `CASCADE` only on pure child rows (e.g. `prescription_items` → `prescriptions`), justified in the PR.
- **Index every FK column** (unless it already leads a unique/compound index) — Postgres does not index FKs automatically; autogenerate does not add these for you.
- Patient name search: trigram index — `CREATE INDEX ix_patients_full_name_trgm ON patients USING gin (full_name gin_trgm_ops)` (pg_trgm is installed by migration 001).
- `jsonb` (never `json`) is allowed for: ABDM/FHIR payload snapshots, flexible form answers, notification payloads. It is **not** allowed for anything you filter/join on routinely or that has a fixed shape — that's a table.
- Partial unique indexes for soft-deleted tables: `CREATE UNIQUE INDEX uq_patients_uhid ON patients(uhid) WHERE deleted_at IS NULL`.

## 11. MongoDB collections

Mongo holds documents, not relations: `clinical_notes`, `fhir_bundles`,
`form_responses`, `abdm_raw_payloads`. Conventions:

- Collection names plural snake_case; field names snake_case (not camelCase) to match Postgres.
- Every document carries `_id` (Mongo ObjectId), plus `id` (UUID string) if the document mirrors a Postgres row, plus `patient_id`/`visit_id` UUID strings for joins, plus `created_at` (ISO-8601 UTC).
- No money, no audit data, no consent state in Mongo — those are Postgres-only.

## 12. Migrations (Alembic)

- Numbering is fixed by the plan: `0001` extensions (done) … `0003` audit … `0004` consent … `0005` departments … `0006` patients … see your issue for your number. File: `migrations/versions/<number>_<slug>.py`, `revision = "<number>"`.
- Coordinate `down_revision` in the team channel — with parallel W1 work, chain gaps happen; Tech Lead resolves ordering conflicts.
- One migration per PR. Never edit a merged migration — write a new one.
- `downgrade()` must work (used in CI teardown). "Irreversible" needs Tech Lead sign-off.
- After creating models: import them in `migrations/env.py` (see the comment there) or autogenerate will emit DROPs for your tables.
- Always **read the autogenerated diff** before committing — autogenerate misses CHECK constraints and triggers; add those with `op.execute()`.
- Test locally: `make migrate`, then `make revision m="..."` should produce an **empty** migration (proves models == schema).

## 13. Reference example

```python
# app/opd/models.py
from sqlalchemy import CheckConstraint, ForeignKey, Index
from sqlalchemy.orm import Mapped, mapped_column
from app.common.db import Base
from app.common.models import UUIDPk, Timestamps, Blame
from app.common.enums import VisitStatus, VisitType

class Visit(Base, UUIDPk, Timestamps, Blame):
    __tablename__ = "visits"

    patient_id: Mapped[str] = mapped_column(ForeignKey("patients.id", ondelete="RESTRICT"), nullable=False)
    facility_id: Mapped[str] = mapped_column(ForeignKey("facilities.id", ondelete="RESTRICT"), nullable=False)
    visit_type: Mapped[str] = mapped_column(nullable=False)
    status: Mapped[str] = mapped_column(nullable=False, default=VisitStatus.REGISTERED)

    __table_args__ = (
        CheckConstraint(VisitStatus.sql_check("status"), name="ck_visits_status"),
        CheckConstraint(VisitType.sql_check("visit_type"), name="ck_visits_visit_type"),
        Index("ix_visits_patient_id", "patient_id"),
    )
```

## 14. PR checklist for any schema change

- [ ] Uses `UUIDPk` + `Timestamps` (+ `Blame` where a person acts)
- [ ] Names follow §3 (reviewer: scan the autogen diff for `ix_`/`uq_`/`ck_`/`fk_` names)
- [ ] Status/enum values exist in `app/common/enums.py` and §7
- [ ] FKs constrained + indexed; no business-identifier FKs
- [ ] No plaintext Aadhaar anywhere in the diff
- [ ] Deletion policy per §5; append-only tables have blocking triggers
- [ ] Migration numbered per plan, has `downgrade()`, autogen diff reviewed
- [ ] `make migrate && make revision m=check` yields an empty migration
