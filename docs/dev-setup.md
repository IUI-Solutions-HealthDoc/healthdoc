# Developer setup

Prerequisites: Docker Desktop (or docker + compose v2), `openssl`, `make`, Git.
Node 20 and Python 3.12 only needed if you run things outside Docker.

## First run

```bash
git clone git@github.com:YOUR_ORG/healthdoc.git && cd healthdoc
make setup        # copies .env, generates dev TLS certs, builds, starts, migrates
```

Then open https://localhost (accept the self-signed cert warning).

| Service | URL | Credentials |
|---|---|---|
| App (nginx) | https://localhost | Keycloak login |
| API docs | https://localhost/api/v1/docs | — |
| API health | https://localhost/api/v1/health · /health/deep | — |
| Keycloak admin | http://localhost:8081/auth | admin / `.env` |
| MinIO console | http://localhost:9001 | `.env` |
| Orthanc (PACS) | http://localhost:8042 | `.env` |
| Postgres / Mongo / Redis | localhost 5432 / 27017 / 6379 | `.env` |

Dev users (realm `healthdoc`, password `devpass`): `dev.receptionist`, `dev.doctor`, `dev.admin`.

## Daily commands

```bash
make up / down / logs / ps
make migrate                     # alembic upgrade head
make revision m="add x table"    # new autogenerated migration
make test                        # backend pytest
make lint                        # ruff + next lint
```

## Where your code goes

**Backend** — one folder per module in `backend/app/<module>/`. Each has a
`router.py` stub already mounted at `/api/v1/<module>`. Add `models.py`
(SQLAlchemy on `app.common.db.Base` — then import it in `migrations/env.py`),
`schemas.py`, `service.py`. Auth: `from app.auth.deps import CurrentUser, require_roles`.
Never read `os.environ` directly — extend `app/common/config.py`.
Responses are auto-wrapped in the envelope; return plain dicts/models.

**Frontend** — routes in `frontend/app/<role>/...` (folders already exist),
shared components in `components/`, API calls through `lib/api.ts` (handles
the envelope + auth header). Keycloak client lands in `lib/auth.ts` (F1-W1-03).

**Migrations** — `backend/migrations/versions/`, numbered per the issue plan
(001 extensions is done; 003 audit, 004 consent, 005 departments, ...).

## Rules that CI/reviewers enforce

Branch `feat/<dev>-<module>-<desc>` off `staging`; PRs ≤ 400 lines; no
self-merges; migration PRs reviewed by Tech Lead; Aadhaar never plaintext;
audit writes in the same transaction as the mutation.

## Troubleshooting

**"port is already in use" / "address already in use"** — something on your
machine already listens on that port (common: local Postgres on 5432, another
dev server on 3000/8000). `make setup` detects this and names the process.
Two fixes:

1. Stop the local service, e.g. `brew services stop postgresql@16`, or
2. Remap just that port in `.env` (uncomment the override, e.g.
   `POSTGRES_PORT=55432`) and re-run `make setup`. Container-to-container
   traffic is unaffected — overrides only change what you reach from localhost.

**Stack half-started after a failed setup** — `make down`, fix the issue, `make setup` again. Data volumes survive `make down`.

**Cert warning in browser** — expected in dev (self-signed). Click Advanced → Proceed.
